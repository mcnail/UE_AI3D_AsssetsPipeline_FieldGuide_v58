# 작업폴더 및 파일 분류 규칙

## 작업폴더

- 하나의 제작 작업은 프로젝트 루트 바로 아래에 `YYMMDD_KEYWORD` 형식의 폴더를 만들어 관리한다.
- 이 문서에서 ‘작업폴더’는 `YYMMDD_KEYWORD` 폴더를 뜻한다. 별도의 `작업폴더`라는 상위 폴더를 두지 않는다.
- `YYMMDD`는 작업을 시작한 날짜의 연도 두 자리, 월 두 자리, 일 두 자리다.
- `KEYWORD`는 전체 기획을 대표하는 키워드다. 대괄호나 별표는 실제 이름에 포함하지 않는다.
- 새 채팅이나 세션에서도 기존 작업을 이어갈 수 있다. 이 경우 기존 작업폴더, 날짜, 기획 키워드와 이미지 번호를 유지한다.
- 이어갈 작업이 명확하지 않으면 기존 폴더와 기획문서를 먼저 확인하고, 그래도 구분할 수 없을 때 사용자에게 확인한다.
- 실제 제작 작업이 시작될 때 작업폴더와 `ref`, `design` 하위 폴더를 만든다.

## 폴더 구성

```text
CONCEPT_MODELING_PROJECT/
├─ AGENTS.md
├─ 지침/
└─ YYMMDD_KEYWORD/                 ← 작업폴더
   ├─ ref/                        ← 프롬프트로 전달하는 레퍼런스 자료
   ├─ design/                     ← 기획 정리 문서
   │  └─ YYMMDD_KEYWORD_design.MD
   ├─ 01_KEYWORD_PROCESSKEYWORD_001.png
   └─ 01_KEYWORD_PROCESSKEYWORD_002.png
```

- `ref`: 프롬프트에 사용하는 레퍼런스 파일 또는 레퍼런스 폴더를 저장한다.
- `design`: 기획 정리 문서를 저장한다.
- 생성 이미지는 해당 작업폴더 바로 아래에 저장한다.

## 기획문서 이름

```text
YYMMDD_KEYWORD_design.MD
```

- 날짜와 `KEYWORD`는 작업폴더 이름과 맞춘다.
- 기존 작업을 이어갈 때는 해당 기획문서를 확인하고 갱신한다.
- 기획문서의 확장자는 `.MD`를 사용한다.

예: `260930_ROBOT/design/260930_ROBOT_design.MD`

## 생성 이미지 이름

```text
##_KEYWORD_PROCESSKEYWORD_###.확장자
```

| 항목 | 의미 | 예시 |
| --- | --- | --- |
| `##` | 작업 단계 번호, 두 자리 | `01`: 섬네일, `02`: 스케치, `03`: 컬러링 등 |
| `KEYWORD` | 전체 기획 키워드 | `ROBOT` |
| `PROCESSKEYWORD` | 현재 단계에서 표현하거나 탐색하려는 내용 | `SILHOUETTE`, `JOINT`, `WARM` |
| `###` | 해당 작업 단계 안에서의 이미지 일련번호, 세 자리 | `001`, `002`, `003` |
| 확장자 | 실제 저장한 이미지 형식 | `.png`, `.jpg`, `.webp` |

- 항목은 밑줄(`_`)로 구분하며, 표기의 `#`나 별표는 실제 이름에 포함하지 않는다.
- 같은 작업 단계에서는 `PROCESSKEYWORD`가 달라져도 일련번호를 이어간다.
- 다음 작업 단계는 일련번호 `001`부터 시작한다.
- 기존 이미지가 있으면 해당 단계의 마지막 번호 다음부터 저장하여 기존 파일을 덮어쓰지 않는다.
- 후속 단계도 두 자리 단계 번호를 사용하고, 정한 단계 번호는 작업 중 일관되게 유지한다.

예:

```text
260930_ROBOT/
├─ ref/
├─ design/
│  └─ 260930_ROBOT_design.MD
├─ 01_ROBOT_SILHOUETTE_001.png
├─ 01_ROBOT_PROPORTION_002.png
├─ 02_ROBOT_JOINT_001.png
└─ 03_ROBOT_WARM_001.png
```
